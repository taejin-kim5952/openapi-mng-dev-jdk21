리소스 신청

기존의 ‘클라우드 신청’과 동일하게 사용자가 인프라를 구성하여 설계를 신청한다. 사용자는 본인이 작성한 신청서의 목록을 확인할 수 있다.

리소스 신청서 목록

- 신청중 :
신청을 진행중인 단계
- 설계요청완료 :
신청을 완료하였지만, 설계자가 확인하지 않아 신청을 취소/재신청할 수 있는 단계
- 설계중 :
설계자가 신청내용을 확인중인 단계
- 설계반려 :
설계 반려처리 되어 사유 확인 후 재신청 가능
- 구축중 :
설계 승인처리 되어 클라우드 구축으로 넘어간 단계
- 구축완료 :
‘리소스 현황’에서 확인 가능하며 변경신청 가능
신청기본정보

- 신청자의 default는 본인이지만, 변경버튼을 이용하여 타인을 지정할 수 있다.
- 개발플랫폼명은 기존의 ‘서비스인프라명’기능을 한다.
- 서비스오픈예정일과 구축희망일은 현재일로부터 7일 이후여야 한다.
인프라구성

- NetworkSArea, OsType, Spec, ServerType, 용도를 입력한 후 추가를 클릭한다.
- 서버를 추가한 후, 데이터볼륨설정 기능을 이용하여 Single Storage를 생성할 수 있다.
- 동일한 구성의 서버를 1대 추가할 때는 ‘복제’, 여러대의 서버나 데이터 볼륨을 포함하여 추가할 때는 ‘고급복제’기능을 이용한다.
LoadBalancer 구성

- NetworkSArea, Algorithm, Port 입력 후 저장을 클릭한다.
- RedirectionMode는 DSR, Protocol은 ANY로 고정되어 있다.
- 추가된 LB에는 Dummy VM이 자동으로 생성 및 연결되며, 삭제시 함께 삭제된다.
- LB추가 후 밸런싱 대상 설정 기능을 이용할 수 있다.
- 신청사항을 입력 후 ‘신청하기’ 버튼으로 설계를 요청한다.
Test Data 등록 요청

Test Data 등록 요청

KT SHUB TEST DATA등록
개요

KT Infra에서 보유한 다양한 유무선 기능 및 자원 활용을 위하여 제공되는 SHUB API를 테스트하기 위한 가상의 DATA를 의미합니다. 서비스 개발 시 API의 사용에 대한 테스트가 필요한 경우 임의의 데이터를 등록하여 API호출에 대한 응답 값을 확인할 수 있도록 지원 합니다.

등록 시 유의사항

1) 작성규칙 해당 Enabler System에서 제공하는 연동 규격서를 참조하여 API에서 사용되는 업무 절차 및 파라미터명을 확인한 후 양식에 개인정보가 없는 가상의 데이터로 작성하도록 하며, 최소한의 정보를 등록 해야 합니다.

2) 테스트 의도 테스트 데이터 등록 요청 시 목적을 “기술지원 메뉴”의 입력 폼에 입력 합니다.

3) 적용 시간 등록 요청 테스트 데이터에 대한 적용은 접수일로부터 해당 Enabler System에 등록되기까지 약 3일(working day기준)정도 소요 됩니다.

4) 기타 OIF_750, OIF_754와 같은 N-STEP 연동 API는 테스트 데이터 등록 요청 시, 가상 정보가 아닌 실제 폰번호 정보로 DATA를 등록해야 하며, DATA유지기간은 1일입니다. 등록된 테스트 데이터의 일부는 사용 기간이 정해져 있으며 연장이 필요한 경우 추가 요청 해야 합니다.

TEST DATA등록 Enabler

- SHUB : 사용자 계약 정보 API
- CAPRI : 인증 API
- N–STEP : 부가서비스 API
- LBS : 측위 API

KT Open API 란

KT Infra에서 보유한 다양한 유무선 기능 및 자원 제공을 위한 Interface를 의미 합니다.
사용자는 KT Open API를 이용하여 새로운 수익 창출이 가능한 비즈니스 개발이 가능합니다.
현재 SHUB, IotMakers, Olleh MAP, gigaGenie, ucloud 등의 서비스에서 Open API를 제공하고 있으며, 향후 지속적으로 증가할 것으로 예상됩니다.

KT Open API SDK 란

KT에서 제공하는 Open API 연동 개발을 위한 통합된 개발 KIT를 의미 합니다. 아래의 목표를 지향 합니다.

연동 플랫폼의 독립적
KT에서 제공하는 API중 Restful API와 SOAP API 에 대하여 플랫폼에 상관없이 하나의 SDK를 이용하여 범용적으로 사용할 수 있습니다.
규격의 유연성
인프라에서 제공하는 규격에 대하여 SDK의 변환 기능을 이용하여 서비스에서 원하는 형식(JSON, XML, MAP, STRING)으로 출력할 수 있으며, 입력값에 대해서도 자유로운 규격(JSON, XML, STRING)으로 입력이 가능합니다.
개발의 편리성
SDK에서 제공하는 기능들을 하나의 Library로 제공하여 사용이 효율적인 개발이 가능하도록 지원 합니다.
